# v0.3.1 engineering validation

## Compatibility envelope

Version 0.3.1 keeps binary save version 3, the v2 migration path, world generator
version 3 and every serialized enum ordinal unchanged. No dependency, renderer, thread
ownership rule or deterministic generation algorithm changed. `Game` still owns update
ordering and all OpenGL/OpenAL calls remain on their existing owning threads.

## Dependency direction

`Game` translates raw `engine.Input` state into reusable command buffers and delegates:

```text
engine.Input -> Game/UI routing -> input.PlayerInteractionSystem -> focused Game commands
                             \-> entity.PlayerMovementSystem -> entity.VoxelPhysics -> World
                             \-> entity.PlayerTreatmentSystem -> Player

World -> Chunk point-light maintenance
Game/other callers -> Raycaster.castInto(caller-owned result)
```

The extracted systems never receive the full `Game` object. Movement depends on
`Player`, `World` and caller-owned command/result buffers. Treatment depends on
`Player`/`ItemStack`. Interaction routing depends on a seven-command execution surface.
Rendering and audio feedback remain orchestration concerns.

## Modified algorithms and invariants

- **Voxel DDA:** normalize once, advance the smallest boundary time, and store the
  opposite step as the hit normal. The origin cell remains excluded, but after the
  first boundary advance a zero-distance adjacent hit is valid.
- **Collision/step:** horizontal axes remain independently sub-stepped for sliding but
  share one step allowance per frame. On collision, physics retries from the original
  position exactly one block higher; it accepts only a completely unobstructed raised
  body and horizontal move, otherwise restoring the original slide-to-wall position.
- **Path reconstruction:** parent traversal must encounter the exact start before the
  cache cap. Any missing link or cap exhaustion is failure, never a partial path.
- **Theft events:** event id plus crate position define the current crime window, while
  a transfer id identifies each physical stack movement. A fixed 16-entry primitive
  window rejects duplicate delivery without collapsing distinct same-type stacks; a
  new event/crate clears it, so no explored-position history accumulates.
- **Runtime lights:** single emitter edits search/update one small emitter list and mark
  the same local/neighbor meshes dirty. Bulk generation/batches still rescan once.
- **Object reuse:** projectile release clears every field before entering a 136-object
  maximum pool. Particle storage remains fixed arrays; ray/movement/input buffers are
  caller-owned and independent.

## Performance evidence

No allocation profiler was available, so no allocation-rate claim is made. Evidence
combines source-level removal, deterministic tests and the built-in frame profiler:

- `Game` hot targeting calls only `castInto` with retained buffers; independent-buffer
  tests prevent overwrite hazards.
- Mesher face-local `new float[4]` and order arrays no longer exist.
- Light counters prove point edits do not invoke full chunk scans.
- Projectile identity is reused and retained capacity is capped at 136.
- NPC perception counters prove the configured query cadence.
- Renderer entity bounds and particle simulation were inspected and already use
  primitive/fixed-array storage.

The final release gate ran on 2026-07-22: `clean build` passed all 223 tests,
`test --rerun-tasks` passed independently, and the exact CI path
`clean releaseArtifacts --no-daemon --console=plain` produced both the fat JAR and the
54,359,312-byte self-contained Windows x64 ZIP. The archive contains `Veylon.exe`, its
Java runtime and the expected native-access/native-library configuration. The previously
variable party-travel integration scenario also passed 20 consecutive isolated
repetitions. The direct-AI harness now expires melee noise in the same order as the
production frame loop, preventing test-only immortal perception events.

The repository's `VEYLON_SMOKE=30` scenario ran for 30.0 seconds at 1600x900 on an
NVIDIA RTX 1000 Ada Generation Laptop GPU with OpenGL 3.3 and OpenAL (16 voices). For
that specific run/seed (`2625248315491670796`) with VSync disabled, `FrameProfiler`
reported 780.8 average FPS, 1.54 ms p95 and 1.86 ms p99; the fortress-approach segment
reported 774.7 average FPS, 1.65 ms p95 and 7.06 ms p99. The smoke runner completed
isolated save/load, fire and fortress approach, met the 60 FPS release gate, reported
zero GL/KHR errors and `withinHardLimits=true`.
These observations describe only that recorded scenario and are not generalized into
an allocation or platform-wide performance claim.

## Deliberate deferrals

- Replacing safe bulk light rebuilds with a dirty-region flood/light redesign would
  risk cross-chunk visuals and is outside a patch release.
- Explosion continuation and a larger save-section allowance have no reachable current
  defect and would weaken workload/corruption guarantees.
- Temperature heat-source scratch and rare explosion victim-list allocations are not
  per-frame target paths; changing their representation was not justified without a
  profiler trace.
