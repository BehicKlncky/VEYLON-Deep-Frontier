# v0.6.0 engineering validation — Signal & Silence

Implementation began at `8a4458b` (v0.5.0) on 2026-09-09; final validation is
recorded on 2026-09-11. This is a presentation release, with eleven ordered
milestone branches merged into `release/0.6.0` through explicit merge commits.
Every milestone passed a complete build before merging. No remote was changed,
no PR/release was created and no push was run.

## Evidence scope

All eleven workstreams are implemented. Automated signal/policy tests, native
execution checks and all final release gates passed as recorded below. Human
listening acceptance is unverified: this record does not claim that anyone
listened for 60 seconds or approved spatial width, music, reverb or perceived
click-free transitions.

The reference host is Windows x64, Intel Core i7-13850HX, Java 25.0.1,
NVIDIA RTX 1000 Ada Generation Laptop GPU, OpenGL 3.3.0 / driver 595.95.
OpenAL and ALC_EXT_EFX initialized successfully on native runs. Portable tests
never create an OpenAL context. No dependency or source audio file was added.

## Compatibility and lifecycle audit

`git diff 8a4458b` is empty for production world, save, entity, combat and AI
packages. Binary save v3, generator version 3 and persisted enum orders remain
unchanged. WeatherSystem.strikeLightning retains the same two RNG calls for X/Z,
loaded-column height query and all fire/fear gameplay actions; only audio uses
the resulting position. New UI enum members are appended and are not saved.

[WorldBootstrap.resetForNewWorld](../../src/main/java/com/veylon/WorldBootstrap.java#L78) resets audio before creating the replacement World, and binds the new query
reference immediately after construction. Successful load uses that path.
Frontend title return and failed frontend load reset audio too. Reset cancels
thunder and pending steals, stops music/one-shots, clears filters/reverb tail and
silences ambience. The native QA path queues distant thunder immediately before
load and asserts zero pending events afterward. A failed live load retains the
current scene through the unchanged SaveSystem validation path.

[AudioManager.shutdown](../../src/main/java/com/veylon/engine/AudioManager.java#L498) releases music/one-shot/ambience sources before their filters, effect slot,
effect, buffers, context and device. Partial initialization also tears down.
The final review cleared EFX detection state on shutdown so reinitialization can
detect a new context, and preserves a stationary fire filter when the ray budget
is exhausted. AudioLifecycleTest proves one dry-fallback log per context lifetime.

Presentation Random remains owned by AudioManager and deliberately excluded from
WorldBootstrap.reseedSimulation; no new seed feeds simulation. All native
submissions, timers and gain/filter updates run on the existing frame thread.
Game is 889 lines, below the enforced 1,000-line budget.

## Deferred with reasons

- Human listening: perceptual equivalence after rate migration, alias audibility,
  60-second loop-period identification, spatial width, reverb taste, wall/shelter
  realism, repetition fatigue, stolen-voice clicks and musical balance cannot be
  established by signal tests or an error-free native run. These remain manual
  acceptance checks; no audio workstream is omitted from implementation.
- Other devices/platforms: native execution was tested on this Windows host and
  its OpenAL device. Forced dry fallback is verified, but macOS packaging,
  driver-specific acoustics and headphone/speaker comparisons were not run here.
- Physical propagation: long rays coarsen sampling to preserve the cap and may
  miss thin distant walls. No diffraction, reflection ray tracing or material
  acoustic model is claimed. Thunder uses four acoustic metres per voxel.
- Native memory: exact PCM and equivalent float sizes are measured; internal
  OpenAL storage and process peak RSS are not claimed.
- Transient state: load intentionally restarts music silence and first-night
  ownership and discards pending thunder. No new audio field is persisted in the
  gameplay save; preference persistence is a separate Properties file.
- Publishing: all branches/tags/artifacts are local by explicit instruction.
  Pushing any v* tag would trigger release-build.yml for three platforms. The
  decision to publish is left to the user.
