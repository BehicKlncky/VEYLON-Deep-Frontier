# v0.4.1 engineering validation

Version 0.4.1 is based on `main` at `07e7731` (v0.4.0). The work is a stability
pass over combat reset, world lifecycle, the event roll ladder and dormant
settlement simulation; it does not change the binary save version, generator
version, serialized enum order or platform baseline.

## Scope and behavior

### World lifecycle

- `PlayerCombatSystem.reset()` clears both melee and ranged cooldown state.
- `TimeSystem`, `WeatherSystem` and `TemperatureSystem` own their `reset()`
  contracts instead of `Game.newWorld` assigning their fields.
- Weather reset clears `flashTimer` and `lightningStrikes`; temperature reset
  drops heat-source positions from the world being replaced.
- `SimulationSystem` plus fast/medium/slow cadence interfaces make that contract
  explicit for every stateful simulation system.

### Event selection

The 13 ordered `else if` branches became an immutable `EventDefinition` table
carrying each cumulative bound, season bias, precondition and effect. The
conversion preserves two non-obvious rules:

1. a rejected rung hands the same roll to the next definition;
2. camp illness searches for a victim in its effect, so an empty camp consumes
   the roll instead of falling through to a lone meteor.

`EventRollLadderTest` was committed before the conversion and records the
distribution across four contrasting world states. It also checks definition
ordering, uniqueness, season bias and side-effect-free preconditions.

### Dormant settlements

`DormantSettlementSimulation` owns off-screen production, consumption, illness,
morale and replenishment. Illness rolls remain position-derived so simulating
another settlement first cannot change an outcome. Replenishment uses a separate
salted random stream; its distribution is unchanged, but its per-seed interval
sequence differs from 0.4.0.

### Endgame and API surface

The beacon integration suite drives all repair stages through the production
interaction commands, including exact costs, Allied trust, victory and a
save/load round trip at stage two. Internal UI screens and debug toggles on
`Game` are package-private; runtime systems and supported gameplay commands
remain accessible.

## Compatibility

- Binary saves remain v3, including the original-v3 EOF path and explicit v2
  migration.
- World generator version remains 3.
- Persisted enum order is unchanged.
- Existing beacon position/stage, weather, time, settlements and world edits
  retain their save layout.
- Java 25, OpenGL 3.3 Core, LWJGL 3.3.6 and the dependency set are unchanged.

## Test structure

The portable `test` task excludes hardware timing and contains 266 deterministic
tests across 55 classes. `performanceTest` contains four opt-in benchmarks:

| Benchmark | Work |
| --- | --- |
| chunk tick | one fast + medium + slow cycle with at least 100 chunks loaded |
| entity tick | one cycle with 40 active entities |
| settlement tick | one real 60-second dormant fixed step with 20 residents |
| save/load | repeated serialization and regeneration of a typical played world |

Every settlement benchmark sample primes the 60-second accumulator, executes a
production 10-second slow tick, and asserts that the dormant step advanced by
exactly one. The fastest-of-seven statistic can therefore no longer select an
empty accumulator pass.

## Release gate

The final local gate ran on 2026-07-30:

- `test --rerun-tasks --no-daemon --console=plain` executed all 266 portable
  tests across 55 classes with zero failures, errors or skips.
- `performanceTest --no-daemon --console=plain` executed all four
  hardware-calibrated benchmarks with zero failures or skips. The task is
  deliberately never up-to-date, so no rerun flag is required. The final run
  measured 0.434 ms chunk tick, 0.402 ms entity tick, 0.010 ms settlement fixed
  step, 0.555 ms save and 251.399 ms load.
- `clean releaseArtifacts --no-daemon --console=plain` completed compilation,
  another 266-test portable pass, fat-JAR creation, `jpackage` and the Windows
  archive.
- `veylon-0.4.1-windows-x64.zip` is 54,409,298 bytes and contains 354 entries.
  It contains `Veylon.exe`, the bundled runtime, README and changelog; its
  launcher config names the Windows LWJGL natives, `veylon-0.4.1.jar` and
  `--enable-native-access=ALL-UNNAMED`.
- `veylon-0.4.1-all.jar` is 7,514,229 bytes and records
  `Implementation-Version: 0.4.1` in its manifest.

The pre-release fixed-seed 30-second OpenGL smoke run passed with
`performanceGate=true`, `glErrors=0`, `khrErrors=0`,
`withinHardLimits=true`, 98.2 average FPS and 10.63 ms p99 frame time. Save/load
and fortress-approach phases both completed.

`javadoc` still reports the nine errors present on v0.4.0; none originate in a
file changed for v0.4.1.

## Known limitations

- Wall-clock baselines are calibrated for the documented i7-13850HX reference
  machine and deliberately run outside portable `test` and packaging jobs.
- The benchmarks measure ticks and serialization, not frames. The OpenGL smoke
  run remains the rendering gate.
- The explanatory event-bound table in `EventSystem.slowTick` JavaDoc duplicates
  the executable definitions and must be updated by hand.
