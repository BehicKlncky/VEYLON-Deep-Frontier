# v0.7.1 engineering validation

Host: Windows x64, Intel Core i7-13850HX, Java 25.0.1+8-LTS-27,
NVIDIA RTX 1000 Ada laptop GPU, NVIDIA 595.95, OpenGL 3.3 / GLSL 3.30.
This is the documented reference CPU/JDK. No OS/platform spoofing was used.

Work started from clean `main` at `baddea9`, fetched/pulled origin with no changes,
and was implemented on `feature/v0.7.1-physical-rain`. The requested deliverable
is the merged source on `main`, which is then tagged `v0.7.1` and pushed so
the release workflow builds and publishes the platform archives.

## Design and review

The 4,000-particle SoA pool is unchanged. World-aware rain integration uses
allocation-bounded DDA, first-face contact, existing block solidity and the
water mesh height. Missing columns terminate without fake impacts or generation.
A bounded column-reference cache avoids boxed map lookups on each drop while
exposing edits immediately; world reseeding releases the old references.
Rain admission stops at 2,400 total particles, secondary admission at 2,800.
Only impacts emit tiny ballistic droplets; secondaries never emit recursively.

The renderer still has alpha and additive submissions, with 13 floats per
instance and velocity at attribute 5. Near-camera fade, distant attenuation,
spawn fade, bounded length, and end-on fallback protect readability. Native
inspection found and fixed a clockwise streak winding error. It also found a
second legacy rain implementation in `Hud`; its rain overlay was removed while
its existing snow overlay remains.

No terrain generation, gameplay weather probabilities, water simulation,
wetness rules, enum ordinals or save layouts changed. Tests cover negative
coordinates, exact first/side/water contact, high-speed thin roofs, unloaded
space, cache invalidation, swap removal, nonrecursive lifetime, seeded replay,
density/intensity, teleport culling, cave rejection, all ordinary emitters,
instance packing and real AmbienceSystem shelter/transition integration.

## Native capture method

After `gradlew.bat installDist`, PowerShell set:

```powershell
$env:VEYLON_SEED='711'
$env:VEYLON_GAME_MODE='creative'
$env:VEYLON_SCENE='physical_rain'
$env:VEYLON_SHOT='4,9,14,19,24,29,34,39,44,49,54,59'
$env:VEYLON_RESOLUTION='1280x720'
$env:VEYLON_VSYNC='false'
$env:VEYLON_FULLSCREEN='false'
$env:VEYLON_GL_DIAGNOSTICS='1'
java --enable-native-access=ALL-UNNAMED -Xmx2G '-Dveylon.dataDir=build/qa/rain-accepted' -cp 'build/install/veylon/lib/*' com.veylon.Main
```

All twelve native PNGs were opened and inspected. The scene exercises normal
rain, storm, shelter/entrance, constructed roof, uneven ground/foliage/water,
running-speed movement, rapid turning, 25%/100% density, starting/stopping rain,
and snow. It is a reproducible scene/seed/phase sequence, not a promise of
byte-identical pixels under different frame timing. Ordinary cold breath and
lightning fire also appear; their smoke puffs are not rain splashes.

The wide views establish depth, roof occlusion, varied streak sizes/orientation,
outdoor rain from shelter, reduced low-density rain and preserved snow.
Still images cannot alone prove continuous collision or temporal smoothness;
fixed-step tests establish causality and native runs exercise the moving scenes.
The `rain_impact` captures freeze the droplet phases, but the droplets are
intentionally tiny and sit near the resolution limit of a still at that camera
distance: the stills confirm placement on the struck face and the absence of
any splash before contact, while the per-frame particle counts and the
fixed-step tests are what actually establish the count and the causality.

### A real finding: benchmark worker isolation

The first combined `performanceTest` run **failed**: `benchmark load` measured
301.221 ms against its 240.00 ms budget. A baseline checkout of `main` at
`baddea9` was built and benchmarked on the same host and measured 223.462 ms,
so the failure was investigated rather than rebaselined.

The cause was JVM-local, not a product regression. `RainPerformanceTest` drives
hundreds of thousands of voxel-column queries through the same call sites the
save/load benchmark uses. Running both in one Gradle test worker leaves those
sites megamorphic, and the later load benchmark inherits the degraded profile.

The fix is `build.gradle` task separation rather than a raised budget: rain
benchmarks carry a `rain-performance` tag, `performanceTest` excludes that tag
and depends on a separate `rainPerformanceTest` task, so each runs in a fresh
worker. After the split, `benchmark load` measures 191–216 ms across runs —
inside budget and at or below the `main` baseline on the same host. No budget
was weakened.

### Native capture telemetry

The twelve-phase `physical_rain` run reported, across all captures:

- peak 1,065 particles against the 2,400 rain admission limit and the unchanged
  4,000-slot pool; the pool never saturated and never stuck at a cap
- peak 2 particle draw submissions, matching the pre-existing alpha/additive
  budget; no additional pass was introduced
- `glErrors=0 khrErrors=0` on every capture
- the 25% density phase drew 125 particles against 730–986 at full density
- the snow phase drew 64 particles on its unchanged emitter path

The `rain_impact` scene captures the causal lifecycle directly: 1 falling drop,
then 4 droplets at contact, then 4 mid-arc, then 0 after expiry. No splash
exists before impact and secondary droplets do not re-splash.

## Honest limitations

- Native graphics were validated on Windows x64 only. macOS and ARM64 native
  execution were not performed; no cross-platform claim is made.
- No release artifacts were packaged **on this host**. `jpackage`, `appImageZip`
  and `releaseArtifacts` were not run locally, so no locally produced v0.7.1
  archive, app image or jar checksum exists, and no OS or platform spoofing was
  used to fabricate one. The `v0.7.1` tag push hands that work to the
  `Release builds` workflow, which packages and validates the Windows x64,
  macOS arm64 and macOS x64 archives on their own runners and publishes them
  with `SHA256SUMS.txt`. Those artifacts were produced by CI, not verified by
  hand here.
- The tag `v0.7.1` was pushed, which triggers automatic publication of a public
  GitHub Release marked `--latest`. The release notes come from
  `docs/releases/v0.7.1.md`.
- Captures are scheduled on wall-clock time, so exact particle pixels vary
  between runs. The scene, seed and phase sequence are reproducible; the frames
  are not byte-identical. Headless tests carry the deterministic guarantees.
- Still images cannot by themselves prove continuous collision across frames.
  Tunneling and causality are established by the fixed-step headless tests.
