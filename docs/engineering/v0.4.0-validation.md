# v0.4.0 engineering validation

## Compatibility envelope

Version 0.4.0 keeps binary save version 3, the authentic v2 migration path, world
generator version 3 and every serialized enum ordinal unchanged. No dependency,
renderer API, thread-ownership rule or deterministic generation algorithm changed.
`Game` remains the composition root and owns the production update order.

The release changes internal ownership rather than player-facing behavior:

```text
Main
  -> Game (composition root, frame/tick ordering and compatibility commands)
       -> focused gameplay collaborators
       -> engine/world/entity/simulation/settlement/UI systems
```

The extracted collaborators share `Game`'s lifetime and are constructed once by
`Game`. Existing input, UI, save and test callers continue to invoke the same
`Game` entry points, which now delegate to the focused owner.

## Design decisions

### Explicit composition instead of a service locator

The 0.4.0 design brief proposed nine mirrored interfaces, nine facades and a service
locator. That exact shape was not implemented. Each facade would still require the
existing system and a `Game` reference for cross-system work, preserving the coupling
while making dependencies implicit.

The extracted concrete collaborators are the current seams. Future interfaces should
be introduced only for a real alternative implementation, a test double that cannot
use the concrete type, or a narrow capability boundary. `Game` remains the explicit
composition root.

### Event roll ladder retained

`EventSystem` still evaluates one random value through 13 ordered `else if` branches.
The thresholds are now named and documented, but the shape is intentionally unchanged:
some failed preconditions continue to later candidates while other matched branches
consume the roll even when their action becomes a no-op. A data-driven conversion is a
behavioral refactor and needs direct boundary/precondition tests first.

### Gameplay behavior preserved

`PlayerCombatSystem.reset()` continues to leave the melee `attackCooldown` unchanged,
matching the pre-refactor world-transition behavior. The method carries a `TODO`; any
change requires an explicit gameplay decision and a regression test rather than being
hidden inside an ownership refactor.

## Verification scope

The deterministic suite contains 240 tests across 51 suites. The 0.4.0 additions
cover:

- fast/medium/slow production tick ordering;
- cross-world queue and transient-action reset;
- world replacement instead of accidental state merging;
- save/load continuation through the real tick entry points;
- strict projectile live/stuck/pool bounds;
- complete simulation RNG reseeding and same-seed replay independence.

The release gate also requires:

1. `git diff --check`;
2. a forced execution of all deterministic tests;
3. the exact Windows `clean releaseArtifacts --no-daemon --console=plain` path;
4. archive inspection for the launcher, bundled runtime and native-access/native JAR
   configuration;
5. the fixed-duration OpenGL smoke scenario with save/load, fire, storm and fortress
   approach under the 60 FPS/runtime-bound gate;
6. the GitHub tag workflow's Windows x64, macOS Apple Silicon and macOS Intel package
   validation before publication.

## Recorded release evidence

The local 0.4.0 release gate ran on 2026-07-29:

- `test --rerun-tasks` executed all 240 tests across 51 suites with zero failures,
  errors or skips;
- `clean releaseArtifacts --no-daemon --console=plain` completed all build, test,
  fat-JAR, `jpackage` and archive tasks;
- `veylon-0.4.0-windows-x64.zip` is 54,401,966 bytes and contains 354 entries,
  including `Veylon.exe`, the bundled runtime and `Veylon.cfg`;
- the packaged configuration selects `natives-windows.jar` and includes
  `--enable-native-access=ALL-UNNAMED`;
- the companion fat JAR `veylon-0.4.0-all.jar` is 7,506,110 bytes.

The automated OpenGL smoke run used seed `20260729`, a 1600×900 framebuffer, VSync
disabled and the 60 FPS release gate. Over 30.0 seconds on an NVIDIA RTX 1000 Ada
Generation Laptop GPU with OpenGL 3.3, it reported:

- 793.3 average FPS, 1.73 ms p95, 2.17 ms p99 and 21.32 ms maximum frame time;
- successful isolated save and load, log-stack ignition and fortress approach;
- 796.3 average FPS, 1.79 ms p95 and 6.71 ms p99 during the fortress approach;
- zero `glGetError` results and zero KHR errors;
- 3 medium-severity NVIDIA shader-state recompilation performance notices;
- `withinHardLimits=true` for NPCs, projectiles, paths, missions, noise, fuses,
  fires, particles, chain reactions and block edits.

These measurements describe this one recorded Windows/NVIDIA scenario. The tag
workflow remains responsible for rebuilding and validating the final Windows x64,
macOS Apple Silicon and macOS Intel archives from the tagged commit.

## Deliberate deferrals

- The EventSystem roll ladder conversion remains a separately testable structural
  refactor.
- A service locator and mirrored interface/facade layer are rejected as specified;
  the underlying broad `Game` access can instead shrink through capability-driven
  constructor dependencies when concrete use cases justify them.
- The cross-world melee cooldown remains unchanged until its gameplay semantics are
  decided.
