# v0.7.0 engineering validation — Stone & Sky

Implementation began at `e963fce` (v0.6.0) on 2026-09-13; this record is written
on 2026-09-16. Eleven ordered milestone branches were merged into
`release/0.7.0` through explicit `--no-ff` merge commits, each merge carrying an
annotated tag, and every milestone passed a complete build before merging.

## Evidence scope

All eleven milestones are implemented. What ran, and what did not, is the most
important thing in this document, because this cycle changed hosts partway
through.

Milestones **v0.6.1 – v0.6.9** were validated on the reference Windows host:
Intel Core i7-13850HX, Windows 10, Java 25, NVIDIA RTX 1000 Ada, OpenGL 3.3.0 /
driver 595.95.

Milestones **v0.6.10 – v0.6.11 and every final gate below** ran on a second
machine: a Linux x64 host with an NVIDIA GeForce RTX 3060 Ti, OpenGL 3.3.0 /
driver 580.173.02, Temurin 25.0.3. `build.gradle` throws
`Unsupported release platform: linux / amd64`, so each Gradle invocation passed
`-Dos.name=Windows 10` to get past the configuration gate. Nothing in the
repository was changed for it and the property reaches only the Gradle JVM, not
the compiled code or the tests; the resolved natives are the Windows ones, which
the headless suite never loads. `gradlew run` is unavailable for the same
reason, so native runs used a hand-assembled classpath with the cached Linux
LWJGL natives and the same `--enable-native-access=ALL-UNNAMED -Xmx2G` the
application plugin passes. That launcher lives in the ignored work directory and
is not committed.

**Consequences, stated plainly.** `releaseArtifacts` and `jpackage` cannot run
on this host, so **no 0.7.0 archive, app image or jar checksum exists**. The
performance and smoke figures come from different hardware than milestones 1–9
and than `docs/PERFORMANCE_BENCHMARKS.md`'s reference machine; they show every
budget passing with margin, and nothing more. macOS archives were not built.
Human acceptance of Creative play — how flight feels, whether the catalog is
ergonomic, whether the permanent-mark warning reads clearly — is **unverified**;
this record does not claim anyone played the mode.

## Save compatibility matrix

Every row below was exercised by a test except the final one, which was measured
directly against a compiled v0.6.0 worktree.

| Save | Loaded by v0.7.0 | Loaded by v0.6.0 |
| --- | --- | --- |
| v2 (0.1.0–0.2.0) | Survival, legacy terrain generator | unchanged |
| v3 written by 0.3.0–0.6.0 | Survival, unmarked | unchanged |
| 0.7.0 Survival world, no palette items | Survival | yes |
| 0.7.0 Creative world, no palette items | Creative, with mark, flight and world controls | loads as Survival; the mark, flight and controls are lost if saved there |
| 0.7.0 save containing palette items | yes | **loads, silently dropping those stacks** |
| Any save with a malformed new section | whole load rejected, live world intact | section skipped as unknown |

The last row corrects a prediction. The brief expected a save containing the new
Creative-only block items to fail cleanly on an older build. It does not:
`readStack` treats an out-of-range ordinal as an empty slot and the stack payload
is fixed width, so the stream stays aligned. Measured by writing a 0.7.0 Creative
save holding six palette stacks and two placed palette blocks and loading it with
a compiled v0.6.0 worktree (`ItemType.values().length` = 91): the load returned
true, the six palette stacks were gone, an unrelated `STONE x9` stack survived,
and both placed blocks came back as `BASALT` and `STONE_BRICK` because no block
id changed. The honest statement is silent item loss, not a clean failure.
Forcing a failure would mean adding a new failure mode to a format that
deliberately tolerates unknown values, so it was not done.

## Survival parity

The central claim of this release is that Survival is untouched. It rests on:

- `SurvivalCreativeParityTest`, written in milestone 1 **before any production
  change**, pinning placement cost, hold-to-mine timing, tool requirements,
  drops and wear, ammunition use, fall damage, fire, starvation, dehydration,
  predator attacks, settler alarms and the absence of flight from a double tap.
- Every Creative test carrying its Survival twin from the same fixture, so a
  gate that accidentally fires in Survival fails.
- `WorldSeedDeterminismTest` and the terrain/camp/kit comparison in
  `ModeSelectionRoutingTest`, which show the same seed produces the same world in
  both modes.
- No existing test expectation was weakened, skipped or deleted. The only edits
  to existing expectations were the version string in `ReleaseVersionTest`,
  appended names in `SerializedEnumOrderTest`, and additive reset assertions in
  `GameLoopIntegrationTest` and `PlayerInteractionSystemTest`.

Skipped RNG draws in Creative are confined to branches that require a Creative
ability or an engaged world control: the bleed, sprain, infection, toxic-fog and
sleep-sickness rolls behind the body gates, the locked-weather branch and the
paused-spawn branch. Survival draw order is unchanged.

## Deferred with reasons

- **Release artifacts and their checksums.** Not producible on this host; the
  Windows machine is needed. This is the one gate from the 0.6.0 cycle that has
  no counterpart here.
- **macOS archives.** Not built, as in 0.6.0.
- **Human playtesting.** Flight feel, catalog ergonomics, confirmation clarity
  and the readability of the new icons at small sizes are judgements a person has
  to make. Captures were inspected for clipping, overlap and legibility; that is
  not the same thing and is not claimed to be.
- **IME and non-Latin keyboard input** into the catalog search field. The
  character callback accepts printable code points the bundled font can draw; a
  Turkish default locale is covered by an automated test, but composed input is
  untested.
- **Other hardware.** Two machines, both NVIDIA, both OpenGL 3.3.
- **Twelve excluded blocks.** Each exclusion and its reason is recorded in
  `CreativePalette` and in the milestone plan; none was re-examined for this
  release.

Publishing remains the user's decision; no remote command was run.
