# VEYLON: Deep Frontier 0.4.0

Version 0.4.0 is an architecture, determinism and maintainability release. It adds
no new gameplay content and does not change saves, generated worlds or the platform
baseline.

## Downloads

| Platform | Asset |
| --- | --- |
| Windows 10/11 x64 | `veylon-0.4.0-windows-x64.zip` |
| macOS Apple Silicon | `veylon-0.4.0-macos-arm64.zip` |
| macOS Intel | `veylon-0.4.0-macos-x64.zip` |

Extract the matching archive, then launch `Veylon.exe` on Windows or `Veylon.app`
on macOS. A separate Java installation is not required. The macOS applications
remain unsigned and unnotarized, so Gatekeeper may require explicit approval from
**System Settings → Privacy & Security** on first launch. Verify archives against
the included `SHA256SUMS.txt`.

## Highlights

- `Game` is now a 1,489-line composition root instead of a 4,380-line monolith.
  Nine focused collaborators own QA automation, combat, mining and placement,
  interactions, consumables, crate transactions, prompt construction, ambience
  and sleep. Existing callers retain the same `Game` command surface.
- Player and simulation tuning values moved into focused constants classes.
  Weather configuration lives with each enum state, making omissions visible at
  compile time.
- All simulation randomness is reseeded from the world seed with independent
  per-system salts. Starting the same seed after another world ran in the process
  now reproduces the same simulation state.
- New architecture and development guides document the composition root, tick
  buckets, save/load lifecycle, extension recipes, deterministic RNG contract and
  known design tradeoffs.
- The deterministic suite now contains 240 tests across 51 suites, including new
  production-loop lifecycle, save/load, projectile-pool and RNG completeness
  coverage.

## Verification

The final local release gate passed a forced execution of all 240 deterministic
tests and the exact Windows CI command,
`clean releaseArtifacts --no-daemon --console=plain`. The resulting
54,401,966-byte Windows x64 archive contains `Veylon.exe`, its bundled Java runtime,
the expected LWJGL Windows natives and the required native-access JVM option.

The fixed-seed (`20260729`) 30-second OpenGL smoke run at 1600×900 completed
save/load, fire and fortress-approach phases. It averaged 793.3 FPS with 1.73 ms
p95 and 2.17 ms p99 frame times, passed the 60 FPS gate, reported zero GL/KHR
errors and kept every monitored runtime collection within its hard limit. The
three NVIDIA shader-state recompilation messages were medium-severity performance
notices, not API errors.

## Compatibility

- Binary save version: **v3**, unchanged.
- Historical v0.2.0/v2 migration: retained and regression-tested.
- World generator: **version 3**, unchanged; existing seed output is preserved.
- Serialized enums: no reordered or removed constants.
- OpenGL 3.3 Core, OpenAL, Java 25, LWJGL 3.3.6 and all dependencies are unchanged.

## Known rough edges

- `EventSystem` retains its ordered 13-branch roll ladder. A future data-driven
  conversion needs direct roll-boundary and precondition tests to preserve its
  current fall-through behavior.
- No mirrored system-interface/facade/service-locator layer was added. The proposed
  design would add indirection without removing `Game` coupling; interfaces remain
  appropriate only when a real substitution or narrow dependency boundary appears.
- `PlayerCombatSystem.reset()` intentionally preserves the pre-refactor melee
  cooldown behavior. Changing that cross-world behavior requires a separate gameplay
  decision and regression test.

See [the engineering validation](../engineering/v0.4.0-validation.md) for the
complete structural and release-gate evidence.
