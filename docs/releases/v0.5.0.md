# VEYLON: Deep Frontier 0.5.0

Version 0.5.0 is a stability and technical-baseline release. It fixes a crash
that could take the game down while you were playing, makes the survival
simulation reproducible from a world seed, and makes loading noticeably faster —
without changing save or world formats. There is no new content.

## Downloads

| Platform | Asset |
| --- | --- |
| Windows 10/11 x64 | `veylon-0.5.0-windows-x64.zip` |
| macOS Apple Silicon | `veylon-0.5.0-macos-arm64.zip` |
| macOS Intel | `veylon-0.5.0-macos-x64.zip` |

Extract the matching archive, then launch `Veylon.exe` on Windows or `Veylon.app`
on macOS. A separate Java installation is not required. The macOS applications
remain unsigned and unnotarized, so Gatekeeper may require explicit approval from
**System Settings → Privacy & Security** on first launch. Verify archives against
the included `SHA256SUMS.txt`.

**Your existing saves still work.** The save format and world generator are
unchanged, and terrain regenerates identically — your shelter is where you left
it.

## Highlights

- **A damaged save can no longer crash the game.** If the power went out during
  a quick save, loading that file could kill the process rather than report a
  problem — and it did so *after* your live world had been released, so you lost
  the session too. Save writes now publish atomically, so a failed write keeps
  the previous file, and a failed quick load leaves the live session untouched.
- **The survival simulation replays from the seed.** Whether a hit opens a
  bleeding wound, whether a fall sprains a leg, whether an untreated wound turns
  septic, whether meat or dirty water poisons you, whether a miserable night
  leaves you sick — none of it reproduced from a world seed. All of it does now.
  Two players on the same seed making the same choices now get the same story.
- **Worlds load about 27% faster.**
- **Ranged combat is more predictable.** In a heavy firefight, releasing a
  half-drawn bow could slow an arrow that was already in the air.
- **Volcanic vents are detected the same way for a fraction of the cost**, along
  with the rest of the twice-a-second environmental checks.

## Fixed

- Corrupt and truncated saves fail cleanly instead of crashing. Five places in
  the save reader used a number from the file directly as an array index or a
  list size; dangerous counts, ordinals and player scalars are now checked at
  the file boundary.
- Save writes flush a complete temporary payload before atomically replacing
  the destination; failed writes cannot truncate the last good save.
- Live-session loads are validated against an isolated game first, and unknown
  world-generator versions are rejected before the current world is touched.
- A save carrying a non-finite player value is rejected rather than loading a
  character who cannot die, heal or eat.
- Fourteen gameplay outcomes now derive from the world seed instead of the
  global random number generator.
- An under-drawn bow shot no longer decelerates an arrow already in flight when
  the projectile cap is reached.
- Powder kegs next to a fire were being armed by two systems at once; one of
  them could never actually arm anything and has been removed.

## Changed

- Loading a world is about 27% faster and the simulation tick is 18–24% cheaper.
  World terrain is bit-identical — this is the same world, generated faster.
- `Game` shrank from 1,496 lines to 886 as world setup, the automated-run
  driver, the front-end states, hotkey routing and the player-environment tick
  moved into named classes. No gameplay rule changed.

## Quality

- 302 deterministic tests across 61 classes, up from 266 across 55.
- Generated terrain is pinned against recorded fingerprints, so a future
  refactor that reshapes worlds fails the build instead of quietly rewriting the
  ground under existing saves.
- A per-system tick profile joins the benchmark suite, and the wall-clock
  baselines were lowered to the new figures rather than left where a regression
  to the previous release would still have passed.
- AI decision RNGs are instance-owned, so a second game or validation load
  cannot perturb another world's seeded outcomes.
- Javadoc doclint passes and runs as part of the normal verification lifecycle.
- The Gradle wrapper verifies the pinned 9.1.0 distribution checksum before
  executing a newly downloaded build tool.
- The fixed-seed 30-second OpenGL release smoke passes at 1600x900 with save/load
  complete, all hard limits respected and zero GL/KHR errors.

## Compatibility

- Save format v3 and world generator version 3 are unchanged; existing saves
  load with identical terrain.
- Persisted enum order is unchanged.
- Java 25, OpenGL 3.3 Core and LWJGL 3.3.6 are unchanged.
