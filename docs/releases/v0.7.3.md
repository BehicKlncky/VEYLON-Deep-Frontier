# VEYLON 0.7.3 — HUD Visual Overhaul

The gameplay HUD is larger and easier to scan, with dark smoked-metal panels,
worn off-white text and restrained teal and amber accents.

## What changed

- **Survival at a glance.** Health, hunger, hydration and stamina now have
  280×18 logical-pixel bars, icons, labels, numbers and explicit LOW/CRITICAL
  warnings. Protein and vitamins remain secondary. Temperatures, wetness,
  fatigue, shelter and load share a compact grid, with larger affliction chips
  and recent events positioned above the panel.
- **A clearer hotbar.** All nine slots grow from 46px to 56px at default scale,
  with larger icons, key numbers and stack counts. A thicker teal border and
  slight lift identify the selected slot. Durability uses a continuous rail;
  freshness uses a segmented rail.
- **Readable action feedback.** Weapon status sits above the hotbar, with larger
  reload and bow-draw progress meters. Interaction prompts gain dark backgrounds
  and amber keycaps. Target and mining feedback are clearer, while the crosshair
  keeps its original aim and spread geometry.
- **Organized context and objectives.** Time, season, weather and biome occupy
  a compact context card. Events, camp standing, quests and navigation share a
  mission card; long lines use an ellipsis to stay within its bounds.
- **A matching Creative panel.** Flight, environment and shelter remain visible
  without survival pressure, medical status or damage/cold vignettes.

Existing saves remain compatible. Gameplay rules, controls, save formats,
inventory, crafting, pause and title screens are unchanged. The larger HUD
components do not change the global default UI scale or add dependencies.

## Validation

The Windows Java 25 suite passed 762 tests across 109 classes, including 58 new
HUD cases for layout bounds, text fitting, Creative/Survival variants and exact
weapon-label behavior. `gradlew.bat build releaseArtifacts --console=plain`
passed on 2026-09-18, including Javadoc and Windows packaging. The local archive
was checked for its executable, bundled runtime, versioned JAR and required
launcher options.

Nineteen final native captures were opened and inspected at actual framebuffer
sizes of 1280×720 and 1920×1080, covering Survival, Creative, bright terrain, fog,
night and requested UI scales of 0.75, 1 and 1.5. Every capture reported one UI
submission, zero GL errors and zero KHR errors. The existing renderer caps 1.5
scale at 1.0 at 720p; 1080p supports 1.5. Maximum affliction counts are covered
by headless layout tests; native captures use a representative sprain.

See the [HUD validation record](https://github.com/BehicKlncky/VEYLON-Deep-Frontier/blob/v0.7.3/docs/graphics/HUD_VALIDATION.md)
for capture filenames, reproduction commands and limitations. These checks do
not constitute a new hardware performance benchmark or full gameplay smoke.

The tag workflow builds and validates Windows x64, macOS Apple Silicon and
macOS Intel archives, then publishes them with `SHA256SUMS.txt`. Each archive
includes Java; a separate Java installation is not required. macOS builds are
unsigned and not notarized.
