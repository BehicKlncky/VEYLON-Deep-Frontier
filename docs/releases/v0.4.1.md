# VEYLON: Deep Frontier 0.4.1

Version 0.4.1 is a stability and maintainability release. It fixes combat and
world-lifecycle state leaks, strengthens endgame and simulation coverage, and
restructures two fragile simulation paths without changing save or world formats.

## Downloads

| Platform | Asset |
| --- | --- |
| Windows 10/11 x64 | `veylon-0.4.1-windows-x64.zip` |
| macOS Apple Silicon | `veylon-0.4.1-macos-arm64.zip` |
| macOS Intel | `veylon-0.4.1-macos-x64.zip` |

Extract the matching archive, then launch `Veylon.exe` on Windows or `Veylon.app`
on macOS. A separate Java installation is not required. The macOS applications
remain unsigned and unnotarized, so Gatekeeper may require explicit approval from
**System Settings → Privacy & Security** on first launch. Verify archives against
the included `SHA256SUMS.txt`.

## Highlights

- The first melee attack after starting or loading a world is no longer blocked
  by a cooldown inherited from the previous world.
- Weather lightning/flash state and cached heat-source positions are cleared when
  a world is replaced, closing three cross-world state leaks.
- The event roll ladder is now an ordered data table. Characterization coverage
  preserves its cumulative bounds, season bias, rejected-rung fall-through and
  the empty-camp illness exception.
- Dormant settlement food, illness, morale and replenishment rules now live in a
  focused simulation class with fixed-step and order-independence coverage.
- The complete three-stage distress-beacon endgame is covered through production
  interactions, including its resource/trust gates and save/load midway through
  repair.
- Simulation systems declare their tick cadence and common world-reset contract.

## Verification

The portable suite contains 266 deterministic, headless tests. Four wall-clock
benchmarks run separately on the documented reference machine so platform release
jobs are not coupled to one computer's timing. The fixed-seed OpenGL smoke gate
continues to cover rendering, save/load, fire and fortress approach.

The final Windows gate reran the portable suite from a clean tree and produced a
validated 0.4.1 fat JAR plus self-contained x64 archive.

See [the engineering validation](../engineering/v0.4.1-validation.md) for the
complete release-gate evidence and benchmark methodology.

## Compatibility

- Binary save version: **v3**, unchanged.
- Historical v0.2.0/v2 migration: retained and regression-tested.
- World generator: **version 3**, unchanged; existing seed output is preserved.
- Serialized enums: no reordered or removed constants.
- OpenGL 3.3 Core, OpenAL, Java 25, LWJGL 3.3.6 and dependencies are unchanged.

Dormant settlement replenishment now draws from its own world-seeded random
stream. The interval distribution is unchanged, but for a given world seed its
sequence differs from 0.4.0.

## Known limitations

- Wall-clock benchmarks cover simulation ticks and save/load, not rendering.
  Rendering performance remains the responsibility of the OpenGL smoke gate.
- Event probabilities have one executable authority (`EventSystem.DEFINITIONS`),
  but the explanatory JavaDoc table beside it is maintained by hand.
